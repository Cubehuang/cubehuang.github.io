Android log 系统介绍

Android中的log系统

在Android系统中，在我们手机连接串口线后，可以通过串口抓取到log，如果我们没有连串口线的话，我们可以通过adb 连接，使用logcat命令来获取log。今天我们就来了解以下logcat的整个框架
我们主要了解的是logcat命令的使用，次之就是了解log系统的框架

1.log系统框架

介绍：
在传统的Linux系统版本中，我们的日志主要来源于内核的日志，用户可以通过logcat获取到内核中的log
在内核中使用printk(Rank,message) 打印我们的日志信息，Rank等级一共有8级

那么日志信息存在哪呢？
在内核中会存在一个环形缓冲区RingBuffer，我们可以使用demsg 命令查看我们的内核中信息，或者通过cat /proc/kmsg 这个目录查看内核中信息（因为环形缓冲区将会和/proc/kmsg目录会进行mmap映射）
应用程序是否可以写内核日志信息呢？
可以的，内核中提供了一个设备节点 /dev/kmsg，用户空间程序可以通过 echo命令往这个 /dev/kmsg中写数据，当然我们也可以通过cat 这个设备节点读取内核日志信息。

三种获取内核日志信息方式：

  • dmesg 命令
  • cat /proc/kmsg
  • cat /dev/kmsg

通过cat获取内核日志信息是，只能读一次，因为cat完后，会将环形缓冲区RingBuffer清掉，demsg命令是不会清掉环形缓冲区。
可以使用 dmesg --follow 实时输出kenel log

在早期的Android 5.0前，我们的Android日志系统主要是和传统Linux日志系统一样，在内核中多设置了几个缓冲区： main system, event radio，并且提供一个设备节点/dev/log/main..system..event..radio 让用户空间能够获取到这些日志信息
也对应的提供了一个命令 让用户可以获取到android 日志——logcat
logcat命令会默认读取 system和main着两个缓冲区的日志信息。我们知道内核中的日志信息是程序在内核总通过printk打出来的。

Android 5.0之后呢，Android将原先的内核的Androidlog系统拿出来放于用户空间中

那么Android的日志信息从哪里来呢？
当然是从用户空间程序中写入的，那么我们就要提供一套接口供应用程序写日志到内核空间中
Android中提供了一个库用于native层 应用层 以及各种库中将log写入到logbuffer中，缓冲区主要分为四个： mian. system event radio，现在还新增了crash,kernel这两个缓冲区。

/system/logging/liblog/ (TODO)

该目录下的代码都是封装到一个liblog.so库中，提供了用户空间程序如何记录日志的各种方法
具体可以README.md 文件进行了解。

其次的话，在用户空间中我们使用了一个守护进程来维护着整个log系统，这个进程就是 logd。

/system/logging/logd/

该进程主要维护通过三个socket管理整个日志系统。
分别为：

  • logd
  • logdr
  • logdw

我们主要强调的是logdr和logdw。
logdw：主要提供其他程序写日志的一个渠道
logdr：主要提供其他程序读日志的一个渠道，例如logcat

  • 缓存区

用户空间中的程序可以使用liblog.so库去写和读日志。写和读的接口都很多。但原理基本上是一致的。内核的日志也一样，用户空间的程序也可以去读写例如使用echo命令 。但是要满足一定的权限。
注：值得注意的就是有时候第三方应用程序的日志输出是通过printf之类的标准函数输出的，系统不会将它写到对应buffer中去，一个方法是使用logwrapper命令来执行第三方应用程序，logwrapper命令可以把第三方应用程序的标准输出重定向到logcat的日志系统中去。
logwrapper(/system/logging/logwrapper/)这个工具将会将第三方库中的其他方式打印的一些log转换通过liblog.so记录对应的缓冲区中，这样我们使用logcat 读出来的日志就能看到三方库的日志信息

缓冲区

  • main： 主缓冲区，
  • system： 存放系统进程打印的一些日志
  • event：主要存放一些时间信息，以特定的tag+信息的形式输出
  • radio：网络相关的日志信息
  • crash：也就是crash崩溃的一些调用栈信息
  • kernel：也就是重定向内核的一些日志信息
  • all：可以表示查看所有缓冲区的日志信息
  • default：默认输出上报 mian,system和crash缓冲区的日志信息（我们在使用logcat命令时候如果什么buffer都不指定，那么默认输出这三个缓冲区的日志）

系统根据log类型，分为main,radio,events,system,crash
frameworks/base/core/java/android/util/Log.java //用于记录main log
frameworks/base/core/java/android/util/Slog.java //用于记录framework log
frameworks/base/telephony/java/android/telephony/Rlog.java //用于记录radio log
frameworks/base/core/java/com/android/internal/os/RuntimeInit.java //内部记录了crash log

数据的格式如下：

第一个字段为名字，第二个字段为数据类型，第三个字段为数据单位

data type 数据类型是以下值中的数字：
1: int
2: long
3: string
4: list

data unit数据单位是从以下列表中取出的数字：

1: Number of objects

4: Number of allocations

s: Number of seconds (monotonic time)
Default value for data of type int/long is 2 (bytes)

三个socket

  • /dev/socket/logd
    • SOCK_STREAM：提供 面向连接的稳定数据传输，即TCP协议
    • logd主要用于接受外部控制命令
  • /dev/socket/logr
    • SOCK_SEQPACKET： 提供连续可靠的数据包连接
    • 客户端通过logdr读取log数据，使用seqpacket，可以让用户可靠地读取数据的同时，一次读取一条log
  • /dev/socket/logw
    • SOCK_DGRAM： 使用不连续不可靠的数据包连接
    • 客户端通过logdw 写入log数据，由于类型为dgram，在非常繁忙时候log可能会丢失，客户端阻塞在写log的调用上

2.logcat命令使用

log的基本格式

06-10 14:07:20.994   976  1459 W ActivityManager: Process com.android.systemui has crashed too many times, killing! Reason: crashed quickly

日期 时间 进程号 线程号 级别logLevel 标签tag 具体信息
06-10 14:07:20.994 976 1459 W ActivityManager Process com.android.systemui has crashed too many times, killing! Reason: crashed quickly

Android中的log等级：

简称 全称级 数值 使用
V VERBOSE 2 Log.v
D DEBUG 3 Log.d
I INFO 4 Log.i
W WARN 5 Log.w
E ERROR 6 Log.e
A ASSERT 7 println

其实还有
F(Fatal)和S(silent)两个等级，S最高

常用命令

  • logcat -b //b:buffer指定要输出log的buffer，
    • logcat -b system //输出的是system缓冲区的日志
    • logcat -b all //输出所有缓冲区的log
    • logcat -b system,main,event//查看三个缓冲区的log
  • logcat -s //s:select 过滤
    • logcat -s “TAG:LogRank”//打印只有TAG的日志信息，并且日志的级别在logLevel以上
    • logcat -s “system_server”//只打印tag为system_server的日志信息
    • logcat -s “system_server:W”//只打印tag为system_server的日志信息，并且log级别在W(warn)以上，Error，等
  • logcat Tag1 Tag2… *:S //只输出 Tag1和Tag2等在命令中tag的日志信息，即可以输出多个TAG的日志
    • *:S 表示，S(Silent)最高级别log，*:S就是表示，只输出S级别以上的log信息，就是什么都不输出，加上前面的Tag1 Tag2条件，就是只输出Tag1 Tag2的日志信息，必须加*:S要不然不生效
  • logcat -c // 清除缓冲区日志信息
    • logcat -b all -c 清除所有缓冲区日志
  • logcat -D //输出各个缓冲区的分割线
  • logcat -f 目录 //不将log输出到屏幕中，将输入到文件中，-f也可以使用>符号重定向代替
    • logcat -f /hsy/hsy.log -r 512 -n 2 //表示将log存储到hsy.log中，-r 512表示文件存储log达到512字节 创建另一个文件存， -n 2 表示一共存两个文件
  • logcat –pid=XXX //查看某个进程的日志信息
  • demsg //打印内核日志信息，
    • demsg -w //连续打印
选项 说明
-b 加载可供查看的备用日志缓冲区，例如 events 或 radio。默认使用 main、system 和 crash 缓冲区集。请参阅查看备用日志缓冲区。
-c, –clear 清除（清空）所选的缓冲区并退出。默认缓冲区集为 main、system 和 crash。如需清除所有缓冲区，请使用 -b all -c。
-e , –regex= 只输出日志消息与 匹配的行，其中 是正则表达式。
-m , –max-count= 输出 行后退出。这样是为了与 –regex 配对，但可以独立运行。
–print 与 –regex 和 –max-count 配对，使内容绕过正则表达式过滤器，但仍能够在获得适当数量的匹配时停止。
-d 将日志转储到屏幕并退出。
-f 将日志消息输出写入 。默认值为 stdout。
-g, –buffer-size 输出指定日志缓冲区的大小并退出。
-n 将轮替日志的数量上限设置为 。默认值为 4。需要使用 -r 选项。
-r 每输出 时轮替日志文件。默认值为 16。需要使用 -f 选项。
-s 相当于过滤器表达式 ‘*:S’；它将所有标记的优先级设为“静默”，并用于放在可添加内容的过滤器表达式列表之前。如需了解详情，请转到介绍过滤日志输出的部分。
-v 设置日志消息的输出格式。默认格式为 threadtime。如需查看支持的格式列表，请参阅介绍控制日志输出格式的部分。
-D, –dividers 输出各个日志缓冲区之间的分隔线。
-c 清空（清除）整个日志并退出。
-t 仅输出最新的行数。此选项包括 -d 功能。
-t ‘‘ 输出自指定时间以来的最新行。此选项包括 -d 功能。如需了解如何引用带有嵌入空格的参数，请参阅 -P 选项。adb logcat -t ‘01-26 20:52:41.820’
-T 输出自指定时间以来的最新行数。此选项不包括 -d 功能。
-T ‘‘ 输出自指定时间以来的最新行。此选项不包括 -d 功能。如需了解如何引用带有嵌入空格的参数，请参阅 -P 选项。adb logcat -t ‘01-26 20:52:41.820’
-L, –last 在最后一次重新启动之前转储日志。
-B, –binary 以二进制文件形式输出日志。
-S, –statistics 在输出中包含统计信息，以帮助您识别和定位日志垃圾信息发送者。
-G 设置日志环形缓冲区的大小。可以在结尾处添加 K 或 M，以指示单位为千字节或兆字节。
–pid= … 仅输出来自给定 PID 的日志。
–wrap 休眠 2 小时或者当缓冲区即将封装时（两者取其先）。通过提供即将封装唤醒来提高轮询的效率。
